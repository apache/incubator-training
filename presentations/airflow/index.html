What is Apache Airflow?

  • Airflow is a platform to programmatically author, schedule and monitor workflows.

  • Developed initially by Airbnb in 2014 and later donated to the Apache Software Foundation, Airflow has become the de facto standard for workflow orchestration in the data engineering ecosystem

Airflow Principles

Each principle has a slide following that explains it, so you don’t need to explain this here.

Airflow Principle: Scalable

What enables scaling of Airflow :

  • Utilizes a message queue (e.g., Redis, RabbitMQ) to coordinate task execution across workers. This enables asynchronous communication between the scheduler and workers

  • Supports multiple executor types (e.g., Celery, Kubernetes) for distributed task execution. This allows Horizontal Scaling

Airflow Principle: Extensible

  • Airflow allows you to create :

    • custom operators

    • custom sensors

    • hooks

    • plugins

This helps extending Airflow functionality while also helping to integrate with any system, define new abstractions, and tailor workflows to your environment seamlessly. 🚀

Custom Operators and Sensors: Airflow allows users to create custom operators and sensors to handle specific tasks and logic that are not covered by the built-in operators.

Hooks: Hooks are interfaces to external platforms and databases, implementing a common interface when possible and acting as building blocks for operators.

Plugins: Airflow’s plugin architecture allows users to extend the platform’s functionality by adding custom modules, operators, sensors, and hooks.

Airflow: Core Components

If required, you can explain each component briefly.

  1. Scheduler

    • The scheduler is responsible for monitoring tasks and DAGs (Directed Acyclic Graphs), triggering scheduled workflows, and distributing tasks to the executor.

    • It parses DAG files at regular intervals and determines when tasks should be executed.

  2. Executor

    • The executor determines how and where tasks are executed.

    • Different types of executors include:

      • SequentialExecutor: Runs one task at a time, useful for debugging.

      • LocalExecutor: Runs multiple tasks in parallel within the same machine.

      • CeleryExecutor: Distributes tasks across multiple worker nodes using Celery.

      • KubernetesExecutor: Runs tasks in separate Kubernetes pods.

  3. Web Server (Airflow UI)

    • Provides a web-based interface to manage and monitor workflows.

    • Allows users to view DAGs, inspect task logs, trigger jobs manually, and manage configurations.

  4. Metadata Database

    • Stores DAG definitions, task states, execution logs, and other metadata.

    • Typically uses PostgreSQL or MySQL in production.

    • The scheduler and webserver interact with the metadata database to track workflow execution.

  5. Workers (if using CeleryExecutor or KubernetesExecutor)

    • Workers execute tasks assigned by the executor.

    • In CeleryExecutor, multiple worker nodes process tasks in parallel.

    • In KubernetesExecutor, each task runs in a separate Kubernetes pod.

  6. DAGs (Directed Acyclic Graphs)

    • DAGs define the workflows in Airflow.

    • A DAG consists of tasks and their dependencies, written in Python.

  7. Task Instances

    • A task instance represents a specific run of a task within a DAG at a particular execution date.

    • Task instances have different states such as running, success, failed, queued, etc.

  8. Triggerer (for Deferrable Operators)

    • Introduced in Airflow 2.x, the triggerer is responsible for handling deferred tasks asynchronously.

    • Helps optimize resource usage by freeing up worker slots while waiting for external events.

Airflow Features

Apache Airflow provides following features:

  • Pure Python

  • Useful UI

  • Robust Integrations

  • Easy to Use

  • Open Source

Airflow Feature: Pure Python

No more command-line or XML black-magic! Everything is Python:

  • create workflows

  • extend

  • python libraries

  • scheduler, executor and workers run Python

Workflow as Code – DAGs are defined using Python scripts, making workflows highly customizable and modular.

Extensibility – Custom operators, hooks, and plugins can be implemented in Python.

No DSL or Special Language – Unlike some workflow tools that use YAML or JSON, Airflow uses standard Python, allowing users to leverage Python libraries.

Python Execution – The scheduler, executor, and workers all run Python code.

Airflow Feature: Useful UI - DAG Filtering

  • all dags

  • active dags

  • paused dags

  • running dags

  • filter by tag

  • filter by name

DAG Visualization – Easily view and monitor DAG execution flows. Task Monitoring – Track task statuses (success, failure, retries) in real time. Trigger & Rerun – Manually trigger DAGs and retry failed tasks. Logging & Debugging – Access detailed logs for troubleshooting. Parameter Tuning – Modify DAG configurations dynamically. User Access Control – Manage permissions and roles efficiently.

Airflow Feature: Useful UI - Cluster Activity

  • Worker Status

  • Task Distribution

  • Queue Health

  • Executor Performance

  • Debuging

Worker Status – Displays active and inactive worker nodes. Task Distribution – Shows how tasks are being assigned across workers. Queue Health – Monitors task queues to prevent bottlenecks. Executor Performance – Helps analyze task execution times and load balancing. Debugging Tool – Useful for identifying failing or stuck tasks on specific nodes.

Airflow Feature: Robust Integrations

Airflow offers robust integrations with :

  • Cloud Platforms

  • Databases

  • BigData Frameworks

Apache Airflow offers robust integrations with various data sources, cloud services, and third-party tools. It supports APIs, databases, cloud platforms (AWS, GCP, Azure), and big data frameworks (Spark, Hadoop, Snowflake), enabling seamless workflow automation across diverse environments.

Airflow Feature: Easy to Use

Anyone with Python knowledge can deploy a workflow. Apache Airflow does not limit the scope of your pipelines; you can use it to build ML models, transfer data, manage your infrastructure, and more.

Apache Airflow provides a user-friendly UI, Python-based workflow definitions, and clear DAG visualizations, making it easy to design, schedule, and monitor workflows. With built-in logging, retry mechanisms, and task dependencies, managing workflows becomes intuitive and efficient for all types of usecases: ML models, data transfer, etc.
