== What Is Apache DeltaSpike?

* A collection of *portable CDI extensions*
* Ready-to-use modules for enterprise Java
* Tested on OpenWebBeans & Weld, across major EE servers
* "Java EE 7 without Java EE 7!" — Duke's Choice Award (2014)

[.notes]
--
Apache DeltaSpike consists of a number of portable CDI extensions that provide
useful features for Java application developers. The project ensures true
portability by testing on different CDI implementations like Apache OpenWebBeans
and JBoss Weld, and on servers including Apache TomEE, WildFly, GlassFish,
Liberty, and Oracle WebLogic. It won a Duke's Choice Award in 2014 for
innovation in Java technology.
--

== CDI Background

* CDI = Contexts and Dependency Injection (JSR 299)
* Introduced in Java EE 6, now part of Jakarta EE
* Key features: type-safe DI, lifecycle contexts, event bus
* CDI SPI enables portable extensions by third parties

[.notes]
--
CDI was introduced as part of Java EE 6 and is now part of Jakarta Enterprise.
It provides type-safe dependency injection, lifecycle management with well-defined
contexts, an event notification facility, and a Service Provider Interface (SPI)
for developing portable extensions — which is exactly what DeltaSpike leverages.
--

== Portable CDI Extensions

A portable CDI extension can:

* Provide its own beans, interceptors, and decorators
* Inject dependencies into its own objects
* Provide context implementations for custom scopes
* Augment or override annotation-based metadata

[.notes]
--
As set out in the CDI specification, a portable CDI extension may integrate with
a CDI container in all these ways. Because they use the standard SPI, portable
extensions work with any spec-compliant CDI implementation — that's the
"portable" in DeltaSpike's name.
--

== DeltaSpike Modules Overview

[cols="1,3"]
|===
| Module | Purpose

| Core | Fundamental API and utility classes
| Bean Validation | CDI-aware ConstraintValidators
| Container Control | Boot/shutdown CDI in Java SE
| Data | Declarative queries, reduced boilerplate
| JPA | Transactional context and scope
| JSF | Multi-window, view-config, new scopes
| Partial-Bean | Generic interface handlers
| Scheduler | Quartz integration with cron support
| Security | Type-safe method-level security
| Servlet | Inject servlet objects, propagate events
| Test-Control | CDI-based testing support
|===

[.notes]
--
DeltaSpike is organized into modules. The Core module is always required and
provides the base API. All other modules are optional — you only include what
you need. Each module follows the same API/Impl split pattern for clean
separation of concerns.
--

== Key Feature: Type-Safe Security

* Annotation-driven security on method calls
* Non-invasive — no changes to business logic
* Foundation for robust access control

[source,java]
----
@Secured(MyAccessDecisionVoter.class)
public void deleteUser(User user) {
    // business logic here
}
----

[.notes]
--
DeltaSpike Security provides annotation-based intercept and security checking on
method calls. You simply annotate your methods and provide a decision voter
implementation. This approach is non-invasive and keeps security concerns
separate from business logic.
--

== Key Feature: Data Module

* Declarative repository interfaces
* Reduces JPA boilerplate to a minimum
* Supports query methods by naming convention

[source,java]
----
@Repository
public interface PersonRepository
    extends EntityRepository<Person, Long> {

    List<Person> findByLastName(String lastName);
}
----

[.notes]
--
The Data module provides a repository pattern similar to Spring Data. You define
an interface extending EntityRepository and declare query methods using naming
conventions. DeltaSpike generates the implementation automatically, dramatically
reducing boilerplate code.
--

== Key Feature: Configuration

* Injectable configuration values
* Multiple ConfigSources with ordinals
* Type-safe access to properties

[source,java]
----
@Inject
@ConfigProperty(name = "app.timeout")
private Integer timeout;
----

[.notes]
--
DeltaSpike's Core module includes a powerful configuration mechanism that
pioneered many ideas later adopted by MicroProfile Config. You can inject
configuration values in a type-safe manner, and DeltaSpike supports multiple
ConfigSources with configurable priority ordinals.
--

== Key Feature: Container Control

* Boot and shutdown CDI containers in Java SE
* Unified API across CDI implementations
* Manage context lifecycles programmatically

[source,java]
----
CdiContainer cdiContainer =
    CdiContainerLoader.getCdiContainer();
cdiContainer.boot();
// ... use CDI beans ...
cdiContainer.shutdown();
----

[.notes]
--
Container Control allows you to start, stop, and manage CDI containers in
Java SE applications — no application server required. This uses a unifying API
that works across OpenWebBeans and Weld, making your SE applications portable.
--

== Key Feature: JSF Integration

* Multi-window handling (WindowScoped)
* Type-safe view configuration
* New scopes: ViewScoped, ViewAccessScoped
* GroupedConversationScoped
* JSF event broadcasting to CDI

[.notes]
--
The JSF module is one of DeltaSpike's most popular. It provides management of
logical windows for browser tab separation, type-safe view-config that lets you
bind metadata like security constraints to views, and several new CDI scopes
designed specifically for JSF applications.
--

== Version History

* *DeltaSpike 1.x* — targets Java EE 6+ (Java 6 minimum)
* *DeltaSpike 1.9.x* — requires Java 8 minimum
* *DeltaSpike 2.x* — targets Jakarta EE 9+ (Java 11 minimum)
* *Current release: 2.0.1* — supporting Jakarta EE

[.notes]
--
DeltaSpike 1.x supported Java EE starting from version 6. The 2.x line
made the jump to Jakarta EE 9 with the jakarta namespace, requiring
Java 11 as a minimum. The current release is 2.0.1.
--

== Getting Started with DeltaSpike

Prerequisites for DeltaSpike 2.x:

* Jakarta EE 9 or later
* Java 11 or later
* A CDI implementation (OpenWebBeans or Weld)
* Maven, Gradle, or manual JAR management

[.notes]
--
To use the current DeltaSpike 2.x line, you need Jakarta EE 9 or later and
Java 11 as a minimum. You'll also need a CDI implementation — either Apache
OpenWebBeans or JBoss Weld. DeltaSpike supports Maven, Gradle, or manual
JAR inclusion.
--

== Maven Setup — BOM Import

[source,xml]
----
<properties>
    <deltaspike.version>2.0.1</deltaspike.version>
</properties>

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.apache.deltaspike.distribution</groupId>
      <artifactId>distributions-bom</artifactId>
      <version>${deltaspike.version}</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
----

[.notes]
--
The recommended approach is to import the DeltaSpike BOM in your
dependencyManagement section. This ensures consistent versions across all
DeltaSpike modules you use. The current version is 2.0.1.
--

== Maven Setup — Core Dependency

[source,xml]
----
<dependency>
    <groupId>org.apache.deltaspike.core</groupId>
    <artifactId>deltaspike-core-api</artifactId>
    <scope>compile</scope>
</dependency>

<dependency>
    <groupId>org.apache.deltaspike.core</groupId>
    <artifactId>deltaspike-core-impl</artifactId>
    <scope>runtime</scope>
</dependency>
----

API at compile scope, implementation at runtime only.

[.notes]
--
At minimum, you need the DeltaSpike Core module. The API is scoped for compile
time and the implementation is included only for runtime. This prevents you from
inadvertently depending on implementation classes and keeps your code portable.
--

== Adding Optional Modules

Add any module by including its API and Impl:

[source,xml]
----
<!-- Example: Data Module -->
<dependency>
    <groupId>org.apache.deltaspike.modules</groupId>
    <artifactId>deltaspike-data-module-api</artifactId>
    <scope>compile</scope>
</dependency>
<dependency>
    <groupId>org.apache.deltaspike.modules</groupId>
    <artifactId>deltaspike-data-module-impl</artifactId>
    <scope>runtime</scope>
</dependency>
----

[.notes]
--
Once you have the BOM imported and Core included, adding optional modules follows
the same API/Impl pattern. Just add the module dependencies you need. The BOM
manages all the versions for you.
--

== Tested Environments

DeltaSpike is tested on:

* *CDI Implementations:* Apache OpenWebBeans, JBoss Weld
* *Application Servers:* Apache TomEE, WildFly, GlassFish, Liberty, WebLogic
* *Containers:* Apache Tomcat (with CDI), Jetty

[.notes]
--
DeltaSpike ensures true portability by running its test suite against multiple
CDI implementations and application servers. If you're running any of these
environments, DeltaSpike has been validated to work there.
--

== Manual Installation (No Maven)

. Download `distribution-full-2.0.1.zip` from the download page
. Extract the archive
. For `.war` projects: copy JARs to `WEB-INF/lib`
. For `.ear` projects: copy JARs to `EAR/lib`

https://deltaspike.apache.org/download.html

[.notes]
--
If you're not using Maven or Gradle, you can download the full distribution
archive from the DeltaSpike website. It contains all the JARs you need.
Just add them to your project's library directory.
--

== DeltaSpike Community

* Established as Apache TLP in April 2013
* 18 PMC members
* Active mailing lists and issue tracker
* Duke's Choice Award winner (2014)

[.notes]
--
DeltaSpike became a top-level Apache project in April 2013. The PMC currently

== Issue Tracker & Source

* *Issue Tracker:* Apache JIRA
* *Source:* https://gitbox.apache.org/repos/asf/deltaspike.git
* File bugs after checking the mailing list first
* Contributions welcome via patches in JIRA

[.notes]
--
All issues are tracked in the Apache JIRA instance. Before filing a new issue,
the community asks that you check the mailing list first — it may be a known
issue or there may be ongoing discussion. Source code is hosted on Apache Gitbox.
--

== How to Contribute

. Subscribe to the dev mailing list
. Check JIRA for open issues
. Submit patches via JIRA
. File an ICLA for larger contributions
. Build trust through consistent participation

[.notes]
--
Contributing to DeltaSpike follows standard Apache practices. Start by
subscribing to the dev list and participating in discussions. For code
contributions, submit patches through JIRA. For larger or sustained
contributions, you'll need to file an Individual Contributor License Agreement.
