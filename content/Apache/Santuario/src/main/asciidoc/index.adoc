== Apache Santuario

image::project-logo.png[Apache Santuario, 500]

Implementation of the primary security standards for XML

[.notes]
--
Apache Santuario provides implementation of XML-Signature Syntax and Processing
and XML Encryption Syntax and Processing. The project name comes from the
Italian/Spanish/Portuguese word for "sanctuary" — a safe place for your XML.
--

== What Is Apache Santuario?

* Implements W3C XML-Signature and XML Encryption standards
* Provides the standard JSR-105 (Java XML Digital Signature) API
* Offers both DOM-based and StAX-based (streaming) implementations
* Licensed under the Apache License, Version 2.0
* Established as an Apache project since June 2006

[.notes]
--
Santuario is the reference implementation for XML security standards in the Java
ecosystem. It's widely used in enterprise applications, web services (SOAP/WS-Security),
and identity federation (SAML).
--

== Why XML Security?

* Digital signatures prove authenticity and integrity of XML documents
* XML Encryption protects confidential data within XML structures
* Essential for SOAP/WS-Security web services
* Required for SAML assertions in identity federation
* Mandated by many government and financial industry standards

[.notes]
--
Even in the age of REST/JSON APIs, XML security remains critical for enterprise
integration, identity protocols like SAML, and regulatory compliance. Any system
dealing with SAML SSO likely depends on Santuario under the hood.
--

== C++ Library Status

* The C++ library has been **officially retired**
* Code frozen at Apache — no further development
* Codebase migrated to the Shibboleth Project
* Shibboleth maintains it as an internal dependency only
* Not supported for third-party use going forward

[.notes]
--
After years of declining C++ maintainer participation, the PMC formally
retired the C++ library. The Shibboleth project took over maintenance
because their identity provider depends on it. For new C++ projects,
look at alternatives like xmlsec1 or your platform's native crypto libraries.
--

== Three Approaches to XML Signature

[cols="1,2"]
|===
| Approach | Description

| JSR-105 API
| Standard Java XML Digital Signature API (DOM-based under the hood)

| Santuario DOM API
| The older, pre-JSR-105 DOM API with full control

| Santuario StAX API
| Streaming API — lower memory for large XML trees
|===

[.notes]
--
For new projects, the JSR-105 API offers portability. If you need streaming
performance for large documents, the StAX API (available since 2.0.0) is the
way to go. The older DOM API is still available for legacy code.
--

== Two Approaches to XML Encryption

[cols="1,2"]
|===
| Approach | Description

| Santuario DOM API
| In-memory DOM manipulation for encryption/decryption

| Santuario StAX API
| Streaming encryption/decryption for large documents
|===

[.notes]
--
XML Encryption allows encrypting portions of an XML document while leaving
the structure visible, or encrypting entire elements. The StAX API is
preferred for large documents to avoid loading the entire DOM into memory.
--

== Initializing the Library

[source,java]
----
import org.apache.xml.security.Init;

// Call once at application startup
if (!Init.isInitialized()) {
    Init.init();
}
----

* Must be called before any cryptographic operations
* Registers algorithm URIs and internal transforms
* Thread-safe — safe to call from static initializer

[.notes]
--
The Init.init() call sets up the algorithm registry and internal
transforms. It's idempotent but must happen before you sign or encrypt
anything. In a web application, do this in a ServletContextListener.
--

== Creating an XML Signature (JSR-105)

[source,java]
----
XMLSignatureFactory fac =
    XMLSignatureFactory.getInstance("DOM");
Reference ref = fac.newReference("",
    fac.newDigestMethod(DigestMethod.SHA256, null),
    Collections.singletonList(
        fac.newTransform(Transform.ENVELOPED, null)),
    null, null);
----

[.notes]
--
This creates a reference that will digest the entire document using SHA-256
with an enveloped signature transform. The empty URI "" means "sign the
whole document." The enveloped transform excludes the signature element
itself from the digest calculation.
--

== Signing the Document

[source,java]
----
SignedInfo si = fac.newSignedInfo(fac.newCanonicalizationMethod(
    CanonicalizationMethod.INCLUSIVE, null),
    fac.newSignatureMethod(
        SignatureMethod.RSA_SHA256, null),
    List.of(ref));

XMLSignature signature = fac.newXMLSignature(si, ki);
signature.sign(signContext);
----

[.notes]
--
SignedInfo bundles the canonicalization method, signature algorithm, and
references. The sign() call performs the actual cryptographic operation.
The signature is inserted into the document at the location specified by
the DOMSignContext.
--

== Verifying an XML Signature

[source,java]
----
NodeList nl = doc.getElementsByTagNameNS(
    XMLSignature.XMLNS, "Signature");
DOMValidateContext valContext =
    new DOMValidateContext(publicKey, nl.item(0));
XMLSignature sig =
    fac.unmarshalXMLSignature(valContext);
boolean valid = sig.validate(valContext);
----

[.notes]
--
Verification locates the Signature element, unmarshals it, and validates
both the signature value and each reference digest. The validate() method
returns true only if everything checks out. Always verify before trusting
signed XML content.
--

== XML Encryption Example

[source,java]
----
XMLCipher cipher =
    XMLCipher.getInstance(XMLCipher.AES_256_GCM);
cipher.init(XMLCipher.ENCRYPT_MODE, symmetricKey);
EncryptedData ed = cipher.getEncryptedData();
ed.setType(EncryptedData.ELEMENT_TYPE);
Document encrypted = cipher.doFinal(
    doc, elementToEncrypt);
----

[.notes]
--
XML Encryption uses XMLCipher to encrypt individual elements or element
content. AES-256-GCM is recommended for new applications. The encrypted
result replaces the original element in the document with an EncryptedData
structure.
--

== StAX Streaming API

* Available since version 2.0.0
* Uses far less memory for large XML trees
* Processes documents as a stream of events
* Supports both signature and encryption
* Ideal for high-throughput scenarios

[.notes]
--
The StAX API is a major differentiator for Santuario. Instead of loading
the entire XML document into memory as a DOM tree, it processes the document
as a stream. This is critical for services handling many large SOAP messages
concurrently.
--

== Supported Algorithms

* **Signature**: RSA-SHA256, ECDSA, EdDSA (since 3.0.2)
* **Digest**: SHA-256, SHA-384, SHA-512; **Canonicalization**: Inclusive, Exclusive C14N
* **Encryption**: AES-128/192/256-GCM, AES-CBC
* **Key Agreement**: ECDH-ES (since 4.0.2)
* **Key Transport**: RSA-OAEP

[.notes]
--
Santuario supports modern cryptographic algorithms. EdDSA support was added
in the 3.0.2 release, and ECDH-ES key agreement in 4.0.2. Legacy algorithms
like SHA-1 and RSA-SHA1 are available but should not be used in new
applications.
--
